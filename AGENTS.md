# AGENTS.md

Инструкции для агентов и людей, которые меняют этот проект.

## Что это

**Noise Canceller** — портативное приложение Windows 11: подавляет шум и убирает чужие
голоса из микрофона, отдаёт очищенный звук другим программам через виртуальный кабель.

Приоритеты:

1. **Подавление шума** (вентилятор, улица, офис).
2. **Удаление фоновых голосов** — target speaker extraction моделью VoxLock.
3. Ручные настройки: пользователь сам выбирает параметры, без «магии».
4. Проверка без установки драйвера: A/B-запись и режим «Проверить в колонках».

Чего нет и не должно быть без отдельного запроса:

- LLM/ассистента;
- телеметрии; единственный сетевой вызов — проверка ревизии модели на huggingface.co по кнопке;
- установки чего-либо без действия пользователя (кроме VB-CABLE по кнопке);
- вывода звука в колонки при обычном включении — только по кнопке проверки.

## Стек

| Слой | Решение |
|---|---|
| Ядро | Rust 2021, `cpal` 0.18 (WASAPI), `rtrb` 0.4, `libloading` 0.8 |
| Модель | **sherpa-onnx 2.0.1** через C API + VoxLock int8 (16 кГц) + GTCRN/DPDFNet (остаточный шум) |
| Оболочка | Tauri 2.12.5, `decorations: false` (свой заголовок) |
| UI | Vue 3 (`<script setup>`) + TypeScript + Vite 8 + Tailwind 4 |
| Сборка | портативная папка: exe + `models/` + `native/` |

## Аудиотракт

```
cpal capture 48k → моно float
  → Resampler 48→16
  → выравнивание уровня (тихий микрофон → −26 dBFS, до +18 дБ; стуки и щелчки
    с высоким пик-фактором уровень не двигают, паузы за уровень речи не считаются)
  → пиковый ограничитель −6 dBFS (стук не перегружает вход модели)
  → буфер 60 мс (кратен 128)
  → sherpa OnlineSpeechDenoiser.Run(chunk, 16000)   (тишина > 360 мс — пропуск)
  → [GTCRN 16 кГц]  — остаточный шум, если включён
  → [VAD-гейт Silero] — закрывает выход в паузах по детектору речи
  → Resampler 16→48
  → DSP: HPF 4-го порядка (100 Гц) → гейт → AGC → лимитер → комфортный шум
  → rtrb → cpal render → «CABLE Input»
```

Инварианты:

- модель работает **только на 16 кГц**; подать 48 кГц — получить ускоренное «бульканье»;
- блок кратен `hop` (128), поэтому 60 мс округляется до ближайшего кратного:
  1024 отсчёта = 64 мс (в логе движка видно фактическое значение);
- **в аудио-колбэках нет блокировок и аллокаций**: настройки читаются из `AtomicU32`,
  DSP пересобирается в потоке обработки по счётчику версии;
- буфер вывода держится около «блок + буфер»: регулятор темпа подстраивает
  асинхронный конвертер, а `render_f32` при нехватке повторяет последний сэмпл **с
  затуханием** (0.985), чтобы пауза не оставляла постоянку и щелчок на возврате.
  Цель кольца адаптивная: `буфер + max(полблока, размер колбэка)` — виртуальный
  кабель иногда просит 200 мс за раз, и фиксированные 82 мс кольца он вычерпывал
  за один колбэк (тысячи underrun в простое). Размер колбэка и счётчики потерь
  пишутся в строку `clock:` раз в 32 с. Перед обработкой блока проверяется, что в
  кольце есть место **на весь блок с запасом** (`out_raw + chunk_out + 64 <=
  max_fill`): иначе блок, который не влезал целиком, обрезался на полуслове, и это
  считалось как `stats.overflows` («Переполнений буфера»), а не `underruns`;
- тишина (< −64 dBFS дольше 360 мс) не гоняется через модель: блок нулей идёт сразу
  в выход, это главная экономия CPU в простое;
- AGC меняет усиление **посэмплово** (сглаживание 30 мс): детектор работает блоками
  по 100 мс, и ступенька усиления на границе блока слышна тихим щелчком в голосе;
  AGC **только поднимает** (`min_gain_db = 0`), громкость выше цели отдаёт лимитеру:
  когда он ещё и резал, любая громкая фраза опускала усиление, а тихая не успевала
  его вернуть — уровень «гулял» на 5 дБ между фразами;
- первые ~0,3 с после стука или начала речи модель ещё не «узнала» голос и почти
  молчит: на это окно её выход поднимается на 3 дБ с плавным спадом, иначе первые
  слова фразы проглатываются. Когда выход **ровно ноль**, буст не помогает, и
  сначала слово просто пропадает (40–400 мс). Заполнять эту дырку пробовали двумя
  способами и **оба откатили**:
  * подмешивать сырой вход (ступеньками и посэмпловым кроссфейдом) — слышно фон
    и чужие голоса, а это ломает главную функцию; пользователь это сразу слышит
    («слышно не только мой голос»);
  * поднимать тихие блоки к недавнему уровню речи (+6 дБ) — вместе с ними
    поднимаются остатки шума, потому что VAD в шумной комнате считает речью почти
    всё (96 % блоков).
  Итог: короткий провал на старте фразы остаётся, зато изоляция честная. Если
  браться снова — только через модель (её же предыдущий выход), а не через микрофон;
- AGC стартует **закрытым** (`target_present = false`, `agc_mix = 0`): пока детектор
  молчит, поднимать нечего. Раньше он в первую секунду поднимал фон на 12 дБ, а
  первое слово выходило на 8 дБ громче остальных — «скачет громкость в начале»;
- усиление выравнивания запоминается в `data/leveler.txt` и подставляется при
  старте: иначе первые слова каждой сессии идут тихо и «раскачиваются» ~2 с.
  Уровень считается по **самой громкой речи последних секунд** (медленно
  затухающий максимум), а не по среднему: с телевизором в комнате среднее
  садится ближе к телевизору, gain уползает к +18 дБ, и первое слово после
  паузы выходит на 8 дБ громче остальных. Блок, который на 8 дБ ниже пика,
  уровень не двигает — это фон, а не говорящий. Первые 1.5 с сессии усиление
  **только опускается**, а завышенное сохранённое сбрасывается сразу на первом
  слове — иначе старт записи выходил на 8–13 дБ громче;
- профиль голоса при записи нормализуется до −20 dBFS: тихая запись (−60 dBFS)
  не совпадает с живой речью, и модель начинает резать своего же говорящего;
- AGC поднимает уровень **только когда в блоке есть речь** (`Chain::set_target_present`):
  вердикт даёт Silero VAD по выходу модели (без VAD — по ослаблению модели, `< 8 дБ`).
  Раньше решало только ослабление, и профильный режим (модель режет своего же
  говорящего на 10–14 дБ) запрещал подъём именно там, где он нужен: фразы
  отличались по громкости на 5 дБ. Поднимать шум это не мешает — тишину держит
  VAD-гейт, остатки добивает GTCRN;
- между микрофоном и выходом стоит асинхронный конвертер (`Slew`): часы устройств
  расходятся, и без него кольцо либо переполнялось (звук обрезался кусками), либо
  пустело (в слова вставлялись нули). Правка считается **по уровню кольца** (это
  интеграл расхождения часов), а не по счётчикам `pushed/pulled`: те прыгают на
  целый блок на границе окна, и от этого шума коэффициент уходил к ±3 % — на слух
  это «голос заговорил быстрее и сменил тембр».
  Цель кольца — `буфер + полблока` (по умолчанию 82 мс), регулятор
  пропорциональный: `step = 1 + 0.0002 · (fill − цель)`, ограничен ±0,5 % и
  двигается не быстрее 0,1 % за 4 с. **Знак важен**: `step > 1` читает вход
  дальше за сэмпл и даёт меньше выходных сэмплов, то есть сушит кольцо;
  перепутанный знак гнал задержку до 300 мс за десять минут. Первые 8 с регулятор
  не трогает — кольцу нужно наполниться. Раз в 32 с в лог идёт
  `clock: fill … ms, ref … ms, step … ppm`, фактическое значение также в
  `stats.slew_ppm` и в строке «Расхождение часов» в «Диагностике». `out_fill`
  хранится как `f32::to_bits`: раньше туда писали число, читали через `from_bits`
  и получали ~0, из-за чего кольцо всегда выглядело пустым;
- **каждая стадия модели отдаёт ровно длину блока** (`FixedStage`): VoxLock и GTCRN
  возвращают столько, сколько успели, и раньше лишнее выбрасывалось (речь
  ускорялась), а недостающее добивалось сырым микрофоном (шум возвращался).
  Теперь излишек ждёт следующего блока, недостача добивается безопасной
  предыдущей стадией. `nc replay` использует тот же `FixedStage`, иначе
  регрессия меряет не то, что слышит пользователь;
- обычный запуск требует кабель; в колонки — только режим проверки;
- **в аудио-колбэках нет блокировок**: сырой звук A/B пишется через `try_lock`
  (занятой мьютекс пропускается, а не ждёт), счётчики — атомики. WAV-файлы пары
  пишет отдельный поток: запись двух 30-секундных файлов в потоке обработки
  останавливала кольцо в самый момент конца дубля;
- **NaN/Inf от модели заменяются тишиной** (`sanitize`, счётчик `bad_blocks`):
  один такой сэмпл отравил бы состояния биквадов до конца сессии, и в наушниках
  была бы тишина без причины в логе;
- потерянные сэмплы считаются отдельно: `stats.overflows` — блок не влез в
  кольцо вывода, `stats.capture_drops` — входное кольцо переполнилось (процессор
  не успевает). Раньше входные потери были молчаливыми;
- **Ctrl+Alt+M** — глобальный mute (`tauri-plugin-global-shortcut`, регистрация в Rust):
  флаг `Shared::muted`, рендер вычитывает кольцо, но пишет нули, чтобы тайминг не
  плыл; состояние видно в `stats.muted` и в плашке на главной. Конфликт с другой
  программой не роняет приложение — пишется в лог.

## Проверка

```powershell
cd app
cargo run -p noise-canceller-cli -- selftest 80   # модель + DSP на эталонном wav
cargo run -p noise-canceller-cli -- run 5 0 0     # живой движок 5 с
cargo run -p noise-canceller-cli -- profile 5     # запись профиля
cargo run -p noise-canceller-cli -- ab 3          # A/B-запись
cargo run -p noise-canceller-cli -- devices       # список устройств с индексами
powershell -File scripts\golden.ps1               # golden-тест, падает при дрейфе
powershell -File scripts\voxlock.ps1 -Atten       # матрица блок/потоки + тихий микрофон
```

Если что-то ведёт себя странно, сначала `data/app.log` (кнопка «Открыть лог» на
вкладке «Настройки»): там старт/стоп движка с устройствами, ошибки потоков,
сбросы сторожа провалов и повторная регистрация хоткея.

Регрессия звука: `powershell -File scripts\regression.ps1 -Count 3` прогоняет
последние A/B через `nc replay` и падает, если провал > 0.4 с, паузы ближе 12 дБ
к речи, громкость уехала от сырого больше чем на 20 дБ или речь вне −55…−10 dBFS.
CI (`.github/workflows/ci.yml`) гоняет clippy `-D warnings`, тесты, сборку фронта
и Tauri.

Те же цифры для одной пары: `nc metrics <raw.wav> <clean.wav>` — печатает уровень
речи, разницу с оригиналом, «паузы тише речи» и самый длинный провал. Ровно это
показывает карточка A/B в интерфейсе (`ab_metrics`), поэтому Rust и Python
считают одно и то же и их можно сверять. Метрики нормированы: «паузы тише речи»
меряется внутри одного файла, так что выходная громкость не может сделать запись
«чище» на бумаге.

**Речь ищется относительно шумового пола самого дубля** (`p10 + 18 дБ`), а не по
абсолютному −50 dBFS: с телевизором в комнате фон стоит на −45 дБ, абсолютный
порог считает его речью, и корректно задавленный шум выглядел как «провал на
0.9 с». Провал — это кадр, где на входе речь, а выход ниже речи дубля на 30 дБ.
Поэтому цифры в карточке совпадают с тем, что слышно, в шумной комнате и в тихой.

Каждая A/B-пара теперь пишет рядом `ab-<stamp>.json` — снимок `Settings`, с
которыми она записана. Иначе через час невозможно понять, почему один дубль
звучит иначе: громкость, AGC, уровень выравнивания и порядок стадий успевают
поменяться. Файл удаляется вместе с парой (ручное удаление и `keep_recordings`).

`nc selftest` проверяет то, что важно для VoxLock: длину (in = out), отсутствие
NaN, «тишина → тишина» (−180 dB) и RTF. `voxlock.ps1` прогоняет матрицу
32–100 мс × 1–8 потоков, а с `-Atten` — ещё и тихий микрофон (−20 dB) с
запомненным усилением. На Ryzen 7 5700X3D 40 мс на одном потоке даёт RTF 1.09 —
это конфигурация, которая не успевает; интерфейс предупреждает об этом, а
сторож RTF показывает плашку, если обработка перестала успевать на любой машине.

Поток обработки сторожит `Engine::healthy()` (в `stats.healthy`): паника в модели
больше не оставляет тишину без следа — UI перезапускает движок и пишет причину.
A/B в интерфейсе слушается с выровненной громкостью (`play_normalized`): иначе
обработанный файл на 10–15 дБ громче сырого и сравнение врёт. Мастер первого
запуска показывает кабель, микрофон и профиль; закрывается в `settings.onboarded`.

Здоровый `selftest 80`:

```
mic   rms=0.0534
model rms=0.0417 peak=0.437
dsp   rms=0.0283 peak=0.301
rtf=0.318 (OK)
```

Если `dsp rms` в десятки раз меньше `model rms` — искать баг в DSP, а не в модели.

## Грабли, на которые уже наступали

1. **PowerShell-вызовы из GUI** (обновление модели, установка кабеля) обязаны идти с
   `CREATE_NO_WINDOW`, иначе мелькает консоль.
2. **Vite 8 убрал esbuild** — нельзя `minify: "esbuild"`, минификатор oxc.
3. **cpal 0.18**: `device.description().name()`, `sample_rate()` → `u32`,
   `build_*_stream(StreamConfig)` по значению, ошибка — `cpal::Error`.
4. **`Producer::slots()`** — свободные слоты; заполненные читает `Consumer::slots()`.
5. **sherpa-onnx не открывает не-ASCII пути** — гнать через `paths::native_safe`
   (в этом репозитории в имени папки типографский дефис U+2011).
6. **`readonly` struct с мутирующим методом** — тихий баг: фильтр остаётся нулевым и
   обнуляет звук. В Rust это ловит borrow checker, в C# не ловил.
7. **Без профиля** sherpa включает авто-режим и ждёт речь; не подсовывать тишину.
8. **Комфортный шум по умолчанию выключен** — постоянный «белый шум» читается как поломка.
9. **Не возвращать звук в колонки автоматически** — только по кнопке проверки.
10. **Разворот безрамочного окна**: `window.maximize()` занимает весь монитор и прячет
    свой заголовок под панелью задач. Разворачиваем вручную по `monitor.work_area()`,
    со сдвигом на кадр окна (`inner_position - outer_position`), иначе по краям
    остаются полосы рабочего стола; при восстановлении `set_size` принимает
    внутренний размер, иначе окно прибавляет 16×9 px на каждый переворот.
    **Свёрнутое окно отдаёт позицию `(-32000, -32000)`** — если её сохранить и
    восстановить, окно открывается за экраном и кажется, что приложение исчезло.
    `save_window` не пишет позицию свёрнутого окна, а `restore_window` проверяет
    точку по `available_monitors()` и при промахе центрирует окно.
11. **Кнопки окна и перетаскивание** идут через Rust-команды (`window_minimize`,
    `window_toggle_maximize`, `window_close`, `window_drag`), а не через ACL-права
    Tauri — права на window-плагин срабатывают ненадёжно.
12. **AEC в режиме проверки противопоказан**: опорный сигнал — наш же выход, то есть
    голос пользователя. Адаптивный фильтр вычитает не только эхо, но и саму речь
    (на A/B видны провалы до −58 дБ внутри фразы). Пробовали NLMS на 512 отсчётов —
    откатили. Настоящий AEC работает, когда опора — голос собеседника, а не свой.
13. **A/B-запись — 30 с, и статус записи важнее путей**: интерфейс опрашивает
    `ab_status` каждые 200 мс. Флаг `running` снимается только после того, как оба
    wav записаны (`Shared::ab_active`); раньше он гас, как только забирали буфер,
    и на 30-секундных файлах кнопки прослушивания не появлялись. Последняя пара
    подхватывается при старте (`last_ab`), прослушивание останавливается повторным
    нажатием (`stop_playback` + `CANCEL` в `playback::play`), а перед новой записью
    прослушивание гасится, чтобы не писать его в микрофон.
14. **Трей-меню над панелью задач сверху**: встроенное меню иконки выравнивается по
    низу (`TPM_BOTTOMALIGN` в `tray-icon`), и при панели задач сверху оно уезжает за
    край экрана. Поэтому меню не прикреплено к иконке: по правому клику вызывается
    `Menu::popup` (muda, `TPM_LEFTALIGN` у курсора) — оно раскрывается вниз. Пункты
    «статус» и «профиль» обновляются перед показом.
15. **Установщик VB-CABLE может быть просто закрыт**: `install_cable` запускает
    `VBCABLE_Setup_x64.exe` и сразу возвращается, поэтому ждать появления устройства
    вечно нельзя. Интерфейс опрашивает список 2.5 минуты, потом снимает «Установка…»
    и пишет, что установка не завершена (плюс напоминание про перезагрузку).
16. **VoxLock теряет говорящего** на 0.2–1 с: модель режет вход на 40+ дБ, хотя
    в микрофоне речь. Уровень тут не виноват (проверяли +6/+10 дБ — не помогает),
    выравнивание тоже. Подмешивать сырой сигнал нельзя: фон по уровню близок к
    тихим словам, получаются «взрывы» (проверяли, 72 срабатывания за 30 с).
    Решение — **сторож провалов**: если модель режет больше 26 дБ три блока
    подряд, вызывается `Denoiser::reset()` (`SherpaOnnxOnlineSpeechDenoiserReset`)
    и в неё заново подаются последние 200 мс входа; выход этой подачи выбрасывается,
    текущий блок считается заново. Провал 0.86 с → 0.12 с, на хорошей записи
    исчезает совсем, уровень речи не меняется. Пре-ролл не длиннее 200 мс: сброс
    стоит ~65 мс CPU в потоке обработки, кольцо вывода (~110 мс) это переживает.
    Между попытками — ~1 с, всего до 4 попыток на эпизод.
    **Сторож взводится по речи на входе, а не по «8 открытым блокам»**: после
    паузы модель давит комнату, открытых блоков нет, и старый сторож не срабатывал
    именно там, где нужен. `InputVoice` ловит скачок уровня микрофона на 8 дБ выше
    среднего за ~3 с; если до этого модель была закрыта ≥0.5 с (`DropoutGuard`
    считает `closed_run`), VoxLock, GTCRN/DPDFNet и их `FixedStage` сбрасываются
    **до** подачи первого слова. Это убирает «первые 1–3 секунды тишины после
    простоя». Повторные сбросы разрешены, пока вход остаётся речью; фон, который
    модель давит штатно, сторож не трогает (нет ни холодного старта, ни открытых
    блоков). `NaN`/пустой выход модели считается провалом (`out_db = −120`):
    раньше сравнения с NaN были `false`, и сторож был слеп на весь эпизод.
    **Максимальное подавление** (`max_suppression_db`, 0 = без предела): если
    модель ослабила речевой блок сильнее предела, в выход плавно (attack 100 мс,
    release 300 мс) подмешивается вход модели (уже выровненный и ограниченный, не
    сырой микрофон), пока ослабление не станет ровно `max`. В паузах cap выключен,
    поэтому фон не поднимается. Сторож при этом считает провалом
    `max(26, max_suppression + 6)`, иначе cap скрыл бы от него все провалы.
    Цифра «Подавление» в плашке меряется только по речевым блокам (входной VAD) и
    ограничивается сверху тем же пределом.
    **AGC начинает новую фразу с измеренного усиления**, а не с нуля: иначе первые
    буквы после паузы шли на 4–12 дБ тише и «раскачивались» секунду-две.
    Выход модели для замера берётся **до** добивки нулями (`FixedStage`), иначе
    сама добивка выглядит как провал. Первую секунду после старта движка сторож
    не срабатывает: модель ещё загружается.
17. **Синхронные команды Tauri выполняются в главном потоке** — любая долгая работа
    в них вешает окно: загрузка модели занимает 1.7–2.1 с, перечисление устройств
    — десятки мс каждые 3 с. Поэтому `start`, `stop`, `list_devices`,
    `default_devices`, `cable_present`, `profile_scores`, `ab_metrics`,
    `last_ab`, `list_recordings`, `prune_recordings` помечены
    `#[tauri::command(async)]`. Команды окна (`window_*`) обязаны остаться
    синхронными: Tauri требует для них главный поток.
18. **Мьютекс движка нельзя держать во время `Engine::start`**: `stats` опрашивается
    из UI каждые 150 мс и вставал в очередь на две секунды, пока грузилась модель.
    `start` собирает движок без блокировки и кладёт его под лок только в конце;
    `stop` сначала забирает движок из слота и только потом join-ит поток.
19. **Виртуальный кабель нельзя выбирать микрофоном**: его capture-сторона — это
    наш же выход, то есть обратная связь, и всё, что играет в кабель, становится
    «говорящим». Автовыбор берёт только настоящие микрофоны, `default_devices` не
    отдаёт кабель, `Engine::start` возвращает понятную ошибку, сохранённый в
    настройках кабель сбрасывается при загрузке. Если микрофон отключён,
    приложение пишет «Микрофон не найден», а не начинает обрабатывать кабель.

## Настройки, которые важны

| Поле | Смысл |
|---|---|
| `input_leveling` | поднимает тихий микрофон до −26 dBFS до модели (до +18 дБ); стуки и паузы не учитываются |
| `residual_denoise` | вторая стадия после VoxLock: `off` / `gtcrn` (по умолчанию) |
| `residual_order` | `after` (по умолчанию) или `before` — где денойзер стоит относительно VoxLock |
| `vad_gate` | Silero VAD закрывает выход в паузах (по умолчанию включён) |
| `voice_isolation` | VoxLock включён/выключен; при `false` модель не грузится вовсе (только шумодав) |
| `max_suppression_db` | предел, на сколько модель может ослабить голос (0 — без предела); в паузах не действует |
| `agc_max_gain_db` | максимальное усиление AGC, по умолчанию **18 дБ**; AGC только поднимает — громче цели отдаёт лимитеру, чтобы уровень не «гулял» между фразами |
| `chunk_ms` | блок модели, 60 мс по умолчанию; меньше — ниже задержка, больше — ниже нагрузка |
| `auto_threads` | подбирать потоки модели по конфигурации машины (по умолчанию **включено**) |
| `denoiser_threads` | потоки sherpa в ручном режиме; при `auto_threads` игнорируется |
| `gate_hold_ms` | сколько гейт остаётся открытым после спада, чтобы не резать концы слов |
| `input_device` / `output_device` | выбранные устройства; `output_device` — только для режима проверки |
| `ab_seconds` | длительность A/B-записи (10/30/60 с), по умолчанию 30 |
| `start_minimized` | стартовать свёрнутым в трей, не показывая окно |
| `onboarded` | мастер первого запуска показан и закрыт |
| `auto_start` | включать обработку при запуске, как только кабель доступен |
| `follow_default_input` | следовать микрофону по умолчанию в Windows |
| `auto_profile` | выбирать профиль с лучшей оценкой |
| `mute_hotkey` / `hotkey_mode` | глобальный mute: сочетание и `toggle`/`hold` (push-to-talk) |
| `basic_ui` | прятать DSP-ползунки под «Дополнительно» |
| `keep_recordings` | сколько последних A/B-пар хранить в `data/recordings` |
| `defaults_rev` | версия заводских значений: при загрузке старый файл мигрируется один раз |

## Производительность

Нагрузка — это RTF (время обработки / длительность звука), а не процент CPU.
На Ryzen 7 5700X3D при 60 мс и 4 потоках: RTF ≈ 0.40, в тишине ≈ 0.00; процесс
занимает ~70 % одного ядра при речи и ~2 % в тишине.
Что даёт что: 40 → 60 мс убирает ~30 % накладных расходов, 2 → 4 потока ещё ~25 %
(и при этом 4 потока дешевле по сумме CPU, чем 2), пропуск тишины убирает почти всё
в простое.

Задержка = модель (24 мс) + содержимое кольца. Кольцо держится на «блок + буфер +
период устройства», поэтому при блоке 60 мс и буфере 50 мс в интерфейсе видно
60–150 мс — это настоящий запас, а не прежние «34 мс», за которыми стояли
пропуски в звуке.

Модель VoxLock берём **int8**: на A/B-записях fp32 отличается от int8 на −48…−52 дБ
относительно сигнала (на слух ничего), но RTF 0.69 против 0.50 — 40 % дороже без
выигрыша. `v2`-модели с HuggingFace **несовместимы** с sherpa 2.0.1 (у enroll
3 выхода вместо 2) — вернуться, когда выйдет новый рантайм. GPU не используем:
CUDA-сборка sherpa занимает 460–570 МБ + cuDNN, работает только на NVIDIA, а на
блоках по 60 мс выигрыша по задержке не даёт.

Проверка: `cargo run -p noise-canceller-cli -- selftest 60 4` (аргументы: мс, потоки,
затухание входа в дБ) и `cargo run -p noise-canceller-cli -- settings` (что реально
загрузилось из settings.json; строка `chunk … threads N (auto|manual M)`).

Потоки модели: при `auto_threads` их число считается от машины и блока
(`recommended_threads`: четверть логических ядер, 2–6; на блоке меньше 60 мс +2, до 8),
иначе берётся `denoiser_threads`. Замеры при 64 мс: RTF 0.83 / 0.69 / 0.48 / 0.38 на
1 / 2 / 4 / 8 потоках — почти весь выигрыш до четырёх, дальше только греет ядра.
На Ryzen 7 5700X3D авто даёт 4 потока. Фактическое значение видно в «Диагностике»
(«Потоков модели») и в логе старта.

Полный тракт: `nc replay <in.wav> <out.wav> [profile.wav] [settings.json]` — выравнивание,
ограничитель, модель и DSP на файле; так проверяются настройки на реальной записи.

Остаточные денойзеры (замер на записи A/B, 100 мс окна):

| Вариант | речь p90 | паузы p50 | «съедено» речи | щелчки |
|---|---|---|---|---|
| выключено | −23.1 | −58.0 | 0 % | 3.6 |
| **GTCRN после VoxLock** | −24.2 | **−80.3** | 22 % | 1.8 |
| GTCRN до VoxLock | −22.5 | −78.2 | 25 % | 3.4 |
| DeepFilterNet3 | −25.4 | −83.0 | 59 % | 9.2 |
| DPDFNet2 | −25.0 | −240 | 45 % | 11.9 |

GTCRN — единственная остаточная стадия: паузы тише на 22 дБ, речь почти не страдает,
щелчков меньше, чем без него. DeepFilterNet3 и DPDFNet из меню убраны: оба на реальной
записи трещат. DPDFNet — из-за собственного VAD (глушит кадры ступенькой), DFN —
из-за самовозбуждения на тихих участках (из входа ±0.002 выдаёт ±0.05 знакопеременных
сэмплов). Крейт `deep-filter-rt` удалён, exe вернулся к ~10 МБ.

Свой спектральный шумодав пробовали и **удалили**: на реальной записи он глушил 45 %
кадров речи и снимал всего 2–4 дБ пола. GTCRN делает это лучше без потерь.

Scicom voice-isolator не берём: лицензия `other`, файла LICENSE в репозитории нет,
условий использования не опубликовано — распространять в портативной сборке нельзя.

Разбор A/B: `nc denoise <in.wav> <out.wav> [hp_hz] [profile.wav]` — гоняет только
модель (без DSP), удобно сравнивать варианты на реальной записи. Известный факт:
в профильном режиме модель при шуме сама давит голос на 10–14 дБ, поэтому AGC
обязан возвращать уровень; при `agc_max_gain_db = 0` голос «пропадает».

## Стиль

- UI-тексты по-русски, идентификаторы по-английски;
- настройки только через `Settings` (serde), сохранение с debounce 300 мс;
- пресеты (Дом/Офис/Улица/Стрим) живут на вкладке «Настройки», не на «Звуке»:
  вкладка «Звук» — только устройства, профиль и проверка;
- всё, что требует перезапуска движка (устройство, профиль, блок, потоки), идёт через
  `restartSoon()` с задержкой 800 мс;
- компоненты UI собственные (`AppSelect`, `AppSwitch`, `AppSlider`, `TitleBar`),
  системные контролы не используем;
- иконки — только из пакета `@lucide/vue` (Lucide, MIT) через общий
  `components/AppIcon.vue`: имя, размер, штрих в одном месте, `non-scale stroke`,
  чтобы линия не истончалась при уменьшении. Самодельные SVG в кнопках не держим
  (разные сетки 10×10 и 16×16 давали «страшные» глифы). Размеры: 16 px в кнопках,
  32–34 px в большой кнопке питания, 12–13 px в заголовке окна;
- пустые состояния не оставляем пустыми, но и не анимируем вхолостую: при
  выключенной обработке спектр — статичная тусклая линия-база, без «дышащей волны»;
- скролл живёт в самой колонке контента (`.app-scroll`, `scrollbar-gutter: stable`),
  а не у края окна: полоса должна стоять рядом с карточками, тонкая и скруглённая;
- уведомления и ошибки живут в **фиксированной колонке** справа-снизу (`AppToast`:
  иконка в цветном круге, заголовок, серое пояснение, крестик) и не участвуют в
  потоке: раньше ошибка была блоком в контенте, и её появление сдвигало все карточки
  вниз. Одинаковые сообщения не дублируются — таймер продлевается, а не появляется
  вторая плашка. Ошибка не исчезает сама, её закрывают крестиком;
- всё, что занимает время, показывает это: обновление списка устройств крутит иконку
  и пишет «Обновляю…», проверка микрофона считает секунды, смена устройства
  блокирует селекты и пишет «Переподключаю устройства…»;
- у каждой настройки на вкладке «Настройки» есть подсказка: `AppLabel` (текст + `?`)
  и `AppHint` (всплывающий пузырь сверху-снизу, `--tip-bg`/`--tip-text`). Подсказка
  объясняет не только «что это», но и на что влияет — это дешевле, чем абзац под
  каждой строкой;
- пока идёт проверка микрофона или запись профиля, спектр показывает **живой**
  сигнал с микрофона: `profile::take_bands()` обновляется в потоке записи, UI
  опрашивает `probe_spectrum` каждые 100 мс.
